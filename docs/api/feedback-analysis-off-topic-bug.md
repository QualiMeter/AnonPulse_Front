# Backend/AI bug: отчёт ИИ не соответствует текстовым отзывам

Статус: воспроизведено на Railway 27 октября 2026 года. Повторный анализ не запускался.

## Сценарий

- Закрытый опрос: `946fe535-c73f-4cf9-a24b-7b98228cd001`.
- Текстовый вопрос `feedback`: `cf1d8997-e5a3-4401-8fae-640926042591`.
- Публичные агрегаты `/api/polls/{pollId}/results` показывают `closed`, `textAnswerCount: 2` для этого вопроса.
- Преподаватель один раз запустил анализ из интерфейса. Статус стал `completed`.
- По словам преподавателя, исходные отзывы относятся к университетским занятиям. Отчёт описывает качество мате и количество чашек, что не соответствует исходным текстам.

## Проверка границы frontend/backend

Преподаватель открыл защищённый GET:

`/api/polls/946fe535-c73f-4cf9-a24b-7b98228cd001/questions/cf1d8997-e5a3-4401-8fae-640926042591/feedback-analysis`

В JSON вернулись те же `pollId` и `questionId`, `status: "completed"`, `answerCount: 2`. Поле `report.summary` уже содержит вывод про мате и чашки. Frontend передаёт ID текущего опроса и вопроса в GET/POST и выводит `analysis.report.summary`, темы, рекомендации и ограничения напрямую из ответа API. Добавлена проверка совпадения обоих ID в ответах GET и POST; несоответствующий ответ теперь не отображается.

## Ожидаемый результат

Отчёт отражает содержание двух отзывов о занятиях и осторожно отмечает малую выборку. Если модель не может обоснованно выделить темы, она не должна придумывать предмет обсуждения.

## Фактический результат

Backend сохраняет и отдаёт семантически посторонний отчёт как `completed`. Проверка схемы и временных ID тем не выявляет смысловое несоответствие.

## Что проверить в backend

1. На тестовых, неперсональных данных сверить строки `poll_text_answers` для `questionId` с обезличенными текстами, переданными в `FeedbackAnalysisInput`.
2. Проверить, какие именно тексты попали в запрос GroqCloud и какой ответ модель вернула. Не выводить реальные отзывы, prompts или секреты в production-логи.
3. Проверить привязку сохранённого `ReportJson` к `QuestionId` и отпечатку ответов.
4. Проверить качество подсказки: текущий `FeedbackAnalysisInput` содержит тексты и временные ID, но не содержит формулировку вопроса или образовательный контекст. Валидация `ValidateAndBuildReport` проверяет структуру и ID, но не обоснованность выводов.
5. Добавить регрессионный тест с вымышленными отзывами об учебных занятиях и проверить, что модель не переносит выводы в контекст товаров/магазина.

Backend в рамках Sprint D не изменялся. Повторный POST без разрешения преподавателя не выполнять.
